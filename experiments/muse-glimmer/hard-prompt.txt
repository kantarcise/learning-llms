Implement a production-minded ExpiringLRU class in Python using only the standard library. Return only Python source, without Markdown fences. Do not include tests. The API and behavior below are the contract; prioritize correctness over cleverness.

API:
  ExpiringLRU(capacity)
  put(key, value, *, now, ttl=None) -> None
  put_many(entries, *, now) -> None
  get(key, default=None, *, now) -> value or default
  snapshot(*, now) -> list of (key, value), least to most recently used

capacity must be an int >= 0, and bool is invalid; otherwise raise ValueError. Keys must be strings (including empty string); values are arbitrary objects and must retain identity. Entries is a one-pass iterable of (key, value, ttl) triples. TTL None means no expiry; numeric TTL must be a finite nonnegative int or float, excluding bool. now must likewise be a finite nonnegative int or float, excluding bool. The computed deadline now + ttl must be finite. Any invalid argument raises ValueError. Times across all successful calls on an instance must be nondecreasing (equal is allowed); backward time raises ValueError. Construction does not establish a time. Do not mutate caller-owned inputs.

At each successful call, purge entries with deadline <= now. A successful get of a live key moves it to most recently used; a miss and snapshot do not change the order of surviving entries. A write replaces a key's value and expiry and moves it to most recently used. ttl=0 removes the key if present and stores nothing. Capacity zero stores nothing but still validates arguments and advances time on successful calls. Evict least recently used entries when capacity is exceeded. get must distinguish a stored None from a miss with a supplied default.

put_many is atomic, including with a generator that raises during iteration: either validate/consume the entire input and apply it, or propagate the exception with absolutely no state change (including expiry purging, LRU order, and last successful time). Invalid entries, including malformed triples, raise ValueError. Iteration exceptions raised by the input itself propagate unchanged. All other invalid calls likewise leave state unchanged. Treat put as a one-element atomic batch. For a valid batch, purge first, apply writes in input order (duplicate keys allowed), then enforce capacity ONCE at the end. A valid empty batch still purges and advances time.

Do not implement time with a real clock, add background threads, or require callers to catch internal implementation exceptions. Average key lookup/update should be O(1), excluding expiry purging, batch validation, and final eviction. Expiry purging may scan the cache. The implementation must work on Python 3.9+.
